# Native fleet client verification

HED-688 adds native fleet-session configuration for Codex, Cursor, Gemini CLI and OpenCode.
It reuses the existing orchestration MCP server, comms broker and dispatch adapters. It does
not add OpenCode worker routing or replace the existing Gemini/Antigravity worker adapter.

## macOS observations — 2026-09-15

Discovery checks used separate temporary workspaces and an isolated home/config directory,
generated by the built `init-client` implementation. No model generation or live provider
dispatch was used to establish these results.

| Installed CLI | Observed result |
| --- | --- |
| Codex CLI 0.147.0 | `codex mcp list --json` discovered `heddle` and `heddle-comms` after the **canonical real path** of the temporary project was trusted. The initial `/var/...` trust key did not match macOS's `/private/var/...` canonical path and the project MCPs were absent. |
| Cursor CLI 2026.09.10-fd3934a | Initially refused the unapproved MCP. After `agent mcp enable heddle-comms` in the isolated workspace, `agent mcp list-tools heddle-comms` connected and listed all 18 tools. |
| Gemini CLI 0.35.3 | The installed CLI's `loadSettings` + `listMcpServers` discovery/transport implementation connected and pinged both generated servers in the isolated trusted workspace. The top-level `gemini mcp list` additionally required an authentication method in the clean home; authenticated model interaction was not exercised. |
| OpenCode 1.14.41 | `opencode --pure mcp list` discovered and connected both generated servers. |

Native approval and authentication remain the client's normal user-facing workflows. The
installer does not disable sandboxing, auto-approve tools, change credentials or overwrite
Claude settings. Polling clients do not advertise Claude channel push presence.

## Automated evidence

`test/client-mcp.test.ts` launches the built servers as real stdio processes using the generated
configurations, proving bidirectional Claude/native and native/native broker messaging,
exclusive inbox cursors, identity binding, no false channel capabilities, and preservation of
worker depth restrictions. These MCP test clients exercise the integration without calling
any language model. `test/client-config.test.ts` checks configuration preservation, backups,
idempotency, dry runs, conflict/error handling, race detection, symlinks, secret-free reports,
and composition with unchanged default Claude initialization.

`npm test -- --maxWorkers=4` initially passed with 2,285 tests passing and one skipped.
`npm run typecheck`, `npm run build`, and built CLI `classes --json` / `packs --json`
smoke checks also passed. Claude's existing comms,
channel/push, adapter, dispatch, hook and installer tests remain in the regression suite.
After the backup/write and marker fixes, the full suite passed again with 2,290 tests and one
skip. The final target-path and test-structure adjustments passed the focused client/config/
init-project suite (80 tests), followed by typechecking, build and CLI smoke checks.

Follow-up source inspection of Cursor CLI 2026.09.10-fd3934a found its `McpSdkClient.callTool`
does not pass timeout options and its bundled MCP SDK defaults to 60,000 ms. Installed startup
guidance therefore directs Cursor agents to Heddle's existing terminal dispatch for delegated
work. OpenCode 1.14.41 passes each MCP entry's `timeout` to `client.callTool`; generated entries
now set 660,000 ms, matching the Codex/Gemini budget. This was verified against
[OpenCode's versioned MCP source](https://github.com/anomalyco/opencode/blob/v1.14.41/packages/opencode/src/mcp/index.ts).

## Boundaries

The integration installs shared project-policy/lifecycle guidance and MCP plumbing. It does
not translate Claude's hook enforcement into the other clients' hook APIs. Messages are polled
at the work boundaries described in the installed instructions; they do not interrupt an active
model turn. Linux terminal/scheduler/notification support is a separate workstream, not a
prerequisite for this macOS integration. Full interactive coding sessions and provider login
flows were not tested by these checks.
